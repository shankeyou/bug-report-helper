# Bug Report Helper

帮助新手把零散报错整理成清晰、便于排查的 Bug 报告的 AI Skill。

遇到问题时，“运行不了”往往不足以让别人帮忙。本项目让 AI 先识别已有证据，再追问关键缺口，最后整理出一份可以复制到 GitHub Issue 的 Markdown 报告。

## 能帮你做什么

- 根据已有信息追问关键问题，减少一次性填写大量字段的负担。
- 整理环境、复现步骤、预期结果、实际结果和错误日志。
- 区分用户反馈、实际验证和未经验证的原因猜测。
- 对信息不足的请求先生成草稿，明确标记“待补充”。
- 提醒并协助替换日志中的敏感内容，便于公开分享。

它是一组供 AI 使用的工作指令，没有独立运行的程序或后端。输出质量取决于所用模型和提供的信息。整理出报告，也不代表已经确认软件存在缺陷。

## 三分钟试用：无需安装

1. 打开 [SKILL.md](SKILL.md)，复制文件全文。
2. 在你使用的 AI 对话中粘贴全文，接着写：
   > 请按以上规则，帮我整理下面的问题。缺少关键信息时先问我。
3. 补上自己的报错、已经做过的操作和期待的结果；可以先从下面的练习输入开始。
4. 回答助手的追问，或者告诉它“我暂时不清楚，请先生成草稿”。
5. 检查报告中的事实和脱敏结果，再自行决定是否公开提交。

这种方式是把技能内容作为对话指令试用，不等同于工具中的原生 Skill 安装。

### 练习输入

下面是模拟练习，不是真实项目的问题记录：

~~~~text
我在 Windows 上运行 python app.py，提示：
ModuleNotFoundError: No module named 'requests'

我不知道接下来需要提供什么信息，请帮我整理成 Bug 报告。
~~~~

合理的第一步是询问项目来源、Python 版本、安装过程等关键缺口。
只凭这一行报错，还不能确认是项目漏写依赖还是当前运行环境配置有问题。

### 在支持 Agent Skills 的工具中使用

下载仓库后，保留名为 bug-report-helper 的文件夹，其中包含 SKILL.md。
按照所用工具的官方文档，将这个文件夹安装到它支持的技能目录，再确认工具发现了该技能。

本项目没有依赖外部脚本，也不要求配置 API 密钥。不同工具的安装位置与调用方式可能不同；第一版尚未完成各工具原生安装的兼容性验证。可以先使用上面的复制方式试用。

## 当前验证范围

第一版的 SKILL.md 已通过本地格式校验；三个模拟案例已按规则逐项静态走查。
这些检查用于发现结构问题和明显的规则冲突，不代表已完成独立模型评测、真实软件复现或用户验收。

案例、示范输出和说明随项目编写，均标注为模拟材料。第一版使用 AI 辅助编写，欢迎通过实际使用持续改进。

## 如何反馈或贡献

先按本说明试用一次，再查看 [现有 Issues](https://github.com/shankeyou/bug-report-helper/issues) 是否已有相同问题。

有改进建议时，提供以下内容即可：

- 脱敏后的输入，以及使用的 AI 工具和模型（如果知道）。
- 助手的实际输出。
- 哪条信息被遗漏、猜测或错误处理，以及你期待的行为。

可以改进提问方式、补充脱敏后的案例、完善说明，也可以提出具体规则修改。请把实际观察与预期结果分开记录，不要把模拟案例写成真实用户反馈。
